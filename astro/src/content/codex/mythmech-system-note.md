# Mythmech

Mythmech is an **inspection layer** for Codex objects.

It does not replace content.
It reveals the **structure inside content**.

Think:

- not a new system
- a lens applied to existing objects

This note is a working surface, not a doctrine.
Mythmech should stay optional, object-first, lightweight, and earned by use.

## Core Goal

Make meaning **inspectable, relational, and generative**.

Specifically:

1. Identify what parts of a scroll actually carry weight.
2. Show how those parts relate through tensor and flow.
3. Allow important parts to become new objects through spawn.
4. Track how ideas evolve over time through lineage.

## What It Operates On

Existing Codex objects:

- scroll
- artifact
- signal
- fragment
- codex
- any other archive object that benefits from inspection

No change to object body is required.

## Conceptual Model

Each object can be decomposed into:

- **Nodes** for meaningful parts such as lines, ideas, or fragments
- **Edges** for relationships between parts
- **Load** for importance or pressure from `critical` to `low`

Together they form a **structure map** or tensor for the object.

## User Experience

Default:

- object reads normally

Optional:

- toggle into **Inspect Mode**

Inspect Mode reveals:

- key nodes
- relationships and flows
- load-bearing elements
- spawn candidates
- lineage context

Reading stays primary.
Inspection stays available on demand.

## Sidecar Data Layer

All Mythmech data lives in the sidecar:

- nodes
- edges
- load values
- lineage
- spawn candidates
- marginalia references

Object content remains untouched.

## Marginalia Integration

Marginalia becomes signal input.

Light tagging enables structure:

- `#seed` for candidate spawn
- `#load` for a load-bearing line
- `#fail` for a breakdown point
- `#link` for a relationship
- `#evol` for a transformation

No heavy authoring burden is required.

## Spawn

Nodes can become new objects.

Examples:

- a single line becomes a new signal
- a concept becomes a new scroll

The system tracks parent and child relationships as it happens.

## Lineage

Objects are connected through:

- origin parents
- derivative children
- cross-links

This creates a living graph of ideas over time.

## Visual Model

Mythmech plates are optional but powerful.

The visual grammar can include:

- a central hinge
- modular node components
- color-coded flows

Flow palette:

- red for pressure
- cyan for control and adjustment
- green for relational grounding

## Design Principles

- Object-first: reading is sacred
- Optional: not all objects need Mythmech
- Lightweight: no heavy authoring burden
- Non-destructive: content stays untouched
- Incremental: the system can start simple and tighten over time

## What Success Looks Like

- You can open any object and see what matters most and how it holds together.
- Insights naturally become new objects.
- Relationships accumulate without heavy manual tracking.
- The system enhances clarity instead of complexity.

## One-Line Definition

Mythmech turns Codex from a collection of writings into a system that:

**reveals what holds meaning together,  
and allows that structure to evolve.**
