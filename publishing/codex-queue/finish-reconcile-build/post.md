# Finish, Reconcile, Build

There is a moment when more possibility stops helping the work.

The project has accumulated directions, studies, feedback, frames, prototypes, open questions, partial builds, and a few decisions that everyone remembers differently. Generative energy is still available. That is not the scarce resource anymore.

The scarce resource is orientation.

What is current?

What was superseded?

Which decisions belong together?

What needs approval?

What can be built now?

What still depends on content, access, or someone else's authority?

I recently described the phase ahead as **finish, reconcile, and build**.

Finish means closing the work that is already near completion. A revision should return to review. A promised comparison should become visible. A component whose behavior is understood should stop living as a loose study.

Reconcile means bringing the different records of the project back into contact. The current design and the submitted design. Desktop and mobile. The design file and the implementation. One person's navigation work and another person's page structure. Feedback from different days that may be using the same word for different things.

Build means moving approved decisions into the system that people will actually use.

These are related activities, but they are not interchangeable.

A polished frame is not necessarily approved. An implemented section is not necessarily faithful to the current design. A note marked complete may still depend on content that has never arrived. A successful prototype may prove a mechanism without proving that the larger service is ready.

Orientation gives those differences a place to remain visible.

I used to think of orientation as the preliminary work before the work begins: gather the files, find the latest version, understand the objective, then proceed.

It is becoming clearer that orientation is continuous.

Every consequential change alters the map. A new review does not simply add tasks. It may change which artifact is authoritative. A build reveals constraints that send a decision back to design. A content choice changes the meaning of an image. An external dependency turns a nearly finished feature into a waiting state.

The map has to move with the work.

This becomes particularly important when several people and agents are operating across a project. Everyone can be productive and still produce drift. One participant closes a layout problem. Another advances the build from an older frame. A third collects feedback without knowing that the underlying question changed yesterday.

The answer is not a larger status document. It is a clearer entrance.

What are we doing now? Which evidence is current? Where is the artifact? What remains unresolved? Who can decide it? What is the next bounded action?

The project should be able to answer those questions without requiring one exhausted person to reconstruct the whole history aloud.

This is also a change in temperament.

Exploration asks what else the work could become. Completion asks what this version is willing to be.

Reconciliation protects the useful discoveries while removing contradictions. Building accepts the discipline of actual behavior, actual content, actual devices, and actual responsibility.

There will always be another possibility.

At some point the work needs a present tense.

Finish what is ready. Reconcile what has drifted. Build what has been decided. Leave the next person a clear way in.
